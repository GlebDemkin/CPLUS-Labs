# CPLUS_Lab4

## Описание проекта

В этом проекте реализована учебная игра по мотивам классического Digger. Игрок управляет машиной Diggermobile, которая перемещается по подземной шахте, роет тоннели, собирает изумруды и золото, толкает мешки золота и защищается от врагов с помощью огненного шара.

Работа выполнена на C++ с использованием объектно-ориентированного подхода. В проекте есть абстрактный игровой объект `GameObject`, от которого наследуются все основные игровые сущности: игрок, враги, изумруды, мешки золота, кучки золота и огненный шар.

Уровни игры задаются во внешних файлах с расширением `.gleb`. Меню также загружаются из внешних `.gleb`-файлов.

## Основные возможности

В игре реализованы:

- игровое поле в виде сетки 15×10;
- перемещение игрока по горизонтали и вертикали;
- рытьё тоннелей при движении через землю;
- сбор изумрудов;
- сбор кучек золота;
- толкание мешков золота влево и вправо;
- падение мешков золота;
- уничтожение игрока и врагов падающим мешком;
- превращение разбившегося мешка в кучку золота;
- появление врагов по одному из точки спавна;
- движение врагов по готовым тоннелям;
- поиск кратчайшего пути врагов к игроку через поиск в ширину;
- выстрел огненным шаром;
- перезарядка выстрела;
- переход на следующий уровень после выполнения условия победы;
- потеря жизни с короткой анимацией взрыва;
- завершение игры при потере всех жизней;
- верхняя игровая панель с номером уровня, жизнями и деньгами.

## Управление

Во время игры используются следующие клавиши:

| Клавиша | Действие |
|---|---|
| `W` или стрелка вверх | движение вверх |
| `S` или стрелка вниз | движение вниз |
| `A` или стрелка влево | движение влево |
| `D` или стрелка вправо | движение вправо |
| `Space` | выстрел огненным шаром |
| `Esc` | пауза / выход в меню |

В меню используются:

| Клавиша | Действие |
|---|---|

| стрелка вниз | перейти к следующему пункту |
| `Enter` | выбрать пункт |
| `Esc` | вернуться назад / закрыть меню |

## Папка `app`

В папке `app` находится класс `Application`.

Он отвечает за:

- создание окна;
- инициализацию GLFW, GLAD и NanoVG;
- загрузку меню;
- главный цикл программы;
- обработку клавиш;
- переключение между состояниями приложения;
- запуск новой игры;
- переходы между меню и игровым экраном.

Основная идея: `Application` управляет приложением целиком, но не содержит конкретную игровую логику. Игровая логика находится в `Game` и `GameWorld`.

## Папка `game`

В папке `game` находится основная модель игры.

Ключевые файлы:

| Файл | Назначение |
|---|---|
| `Game.h` | фасад игровой части для `Application` |
| `GameWorld.h / GameWorld.cpp` | главный класс игрового мира |
| `Level.h` | хранение данных загруженного уровня |
| `LevelLoader.h / LevelLoader.cpp` | загрузка уровня из `.gleb`-файла |
| `Direction.h` | направления движения |
| `GameState.h` | состояния игры |
| `InputState.h` | состояние ввода игрока |
| `TileType.h` | тип клетки уровня |
| `Vec2i.h` | координаты клетки |

`GameWorld` хранит живое состояние игры: карту, объекты, игрока, врагов, деньги, жизни, таймеры смерти и перехода уровня.

`Level` хранит данные, прочитанные из файла уровня. После загрузки данные из `Level` переносятся в `GameWorld`, и дальше уже `GameWorld` изменяет карту во время игры.

## Папка `objects`

В папке `objects` находятся игровые сущности.

Главный базовый класс:

```cpp
class GameObject
```

От него наследуются:

| Класс | Назначение |
|---|---|
| `Player` | игрок Diggermobile |
| `Nobbin` | враг |
| `Emerald` | изумруд |
| `GoldBag` | мешок золота |
| `GoldPile` | кучка золота |
| `Fireball` | огненный шар |

`GameObject` хранит общие свойства объектов:

- позицию на сетке;
- активность объекта;
- метод `getType()`;
- метод `update()`.

Это позволяет хранить разные игровые сущности в одном контейнере:

```cpp
std::vector<std::unique_ptr<GameObject>> objects;
```

Во время обновления мира вызывается:

```cpp
object->update(*this, deltaTime);
```

За счёт виртуальных методов у каждого наследника выполняется своя логика.

## Отрисовка земли

Земля в текущей реализации не рисуется через `PixelSprite`.

Такое решение принято потому, что земля занимает большую часть карты. Если каждую клетку земли рисовать как пиксельный спрайт 16×16, то на каждом кадре создаётся слишком много маленьких графических примитивов. Это сильно нагружает отрисовку и может вызывать подвисания.

Поэтому земля теперь рисуется напрямую в `Renderer::drawLevel()` простыми фигурами NanoVG:

- внешний тёмно-коричневый квадрат;
- внутренний коричневый квадрат;
- несколько маленьких жёлтых квадратиков внутри клетки.

Так карта остаётся визуально похожей на шахту, но отрисовка становится значительно легче.

Тоннель рисуется как тёмный фон игрового поля. Когда игрок копает землю, клетка меняет тип с `TileType::Earth` на `TileType::Empty`, и на её месте остаётся пустое пространство тоннеля.

## Отрисовка игровых объектов

Игрок, враги, изумруды, мешки золота, кучки золота и огненный шар рисуются через `PixelSprite`.

`PixelSprite` хранит изображение как набор строк:

```cpp
PixelSprite sprite = makeSprite({
    "................",
    "...RRRRRR.......",
    "...RCCCCR.......",
    "................"
});
```

Каждый символ соответствует цвету из палитры:

```cpp
{ 'R', {220, 34, 30, 255} }
{ 'C', {95, 205, 235, 255} }
{ '.', {0, 0, 0, 0} }
```

Символ `.` используется как прозрачный пиксель. Его не нужно делать цветным, потому что иначе прозрачные области всех спрайтов начнут рисоваться как обычные квадраты.

## Формат уровня `.gleb`

Уровень задаётся текстовым файлом.

Пример структуры:

```txt
LEVEL 1
SIZE 15 10
PLAYER 7 9
ENEMY_SPAWN 14 1
ENEMY_COUNT 3

MAP
###############
#.....E....$..#
#.............#
#..#####......#
#.............#
#.....E.......#
#........$....#
#.............#
#.............#
#......P......#
END
```

Основные команды:

| Команда | Значение |
|---|---|
| `LEVEL` | номер уровня |
| `SIZE` | размер карты |
| `PLAYER` | стартовая позиция игрока |
| `ENEMY_SPAWN` | точка появления врагов |
| `ENEMY_COUNT` | количество врагов |
| `MAP` | начало карты |
| `END` | конец описания уровня |

Символы карты:

| Символ | Значение |
|---|---|
| `#` | земля |
| `.` | тоннель |
| `P` | позиция игрока |
| `E` | изумруд |
| `$` | мешок золота |
| `G` | кучка золота |

## Игровая логика

Игрок перемещается по клеткам. Если игрок входит в клетку земли, клетка очищается и становится тоннелем.

Изумруды собираются автоматически при входе игрока в клетку с изумрудом.

Мешок золота можно толкать только горизонтально. Если под мешком появляется пустая клетка, он начинает падать. Падающий мешок может раздавить игрока или врага. Если мешок пролетел больше одной клетки, при остановке он разбивается и превращается в кучку золота.

Враги `Nobbin` не умеют копать землю. Они двигаются только по готовым тоннелям. Для движения к игроку используется поиск в ширину. `GameWorld` строит кратчайший путь по проходимым клеткам и возвращает врагу только первый шаг этого пути.

Игрок может стрелять огненным шаром. Огненный шар летит по прямой, уничтожает врага при столкновении и исчезает при попадании в препятствие.

Уровень считается пройденным, если выполнено одно из условий:

- собраны все изумруды;
- уничтожены все враги.

## Сборка проекта

Для сборки используется CMake и Ninja.

Собирать проект лучше из терминала разработчика Visual Studio, чтобы был доступен компилятор MSVC.

Проверить наличие компилятора можно командой:

```powershell
cl
```

Если команда не найдена, значит открыт обычный PowerShell, а не Developer PowerShell.

## Сборка Debug

```powershell
cmake --preset ninja-debug
cmake --build --preset ninja-debug
```

Запуск Debug:

```powershell
.\out\build\ninja-debug\CPLUS_Lab3_Digger.exe
```

## Сборка Release

```powershell
cmake --preset ninja-release
cmake --build --preset ninja-release
```

Запуск Release:

```powershell
.\out\build\ninja-release\CPLUS_Lab3_Digger.exe
```

## Полная пересборка

Если проект собирается некорректно или CMake использует старые настройки, можно удалить папку сборки.

Для Debug:

```powershell
Remove-Item -Recurse -Force .\out\build\ninja-debug
cmake --preset ninja-debug
cmake --build --preset ninja-debug
```

Для Release:

```powershell
Remove-Item -Recurse -Force .\out\build\ninja-release
cmake --preset ninja-release
cmake --build --preset ninja-release
```

Если нужно полностью сбросить все сборочные файлы:

```powershell
Remove-Item -Recurse -Force .\out
```

После этого нужно заново выполнить конфигурацию и сборку.


## Краткий итог

Проект реализует учебную версию Digger на C++ с использованием GLFW, OpenGL, GLAD, NanoVG и CMake.

Основная архитектура строится вокруг `GameWorld`, который хранит состояние игры, и `GameObject`, от которого наследуются все игровые сущности. Уровни и меню задаются во внешних `.gleb`-файлах. Игровые объекты рисуются через символьные пиксельные спрайты, а земля отрисовывается упрощёнными фигурами NanoVG для повышения производительности.
